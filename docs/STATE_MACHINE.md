# Статусы заявки — целевая модель

`Черновик → Подана → (Одобрено | На проверке | Нужны документы | Отказ)`.

- Если запрошен обязательный документ: `Нужны документы → На проверке` **после загрузки клиентом**.
- `На проверке → Одобрено / Другие условия / Нужны документы / Отказ`.
- `Другие условия → Условия приняты` при принятии или `Закрыта` при отклонении.
- `Одобрено → Условия приняты → На подписании → Подписано → Выдано (модель)`.

> Приведённая схема — целевая логика *общего* кредитного конвейера. Она не проверяется сервером в загружаемом staff-only HTML. В текущем демо сотрудник может изменить статус локально, в том числе из состояний, которые в готовом продукте должны блокировать изменение.

После серверной интеграции сотрудники могут выполнять только допустимые действия; backend должен возвращать `409 Conflict` при недопустимом переходе и сохранять аудит каждого изменения. См. `diagrams/states.png`.
