# ALFA PULSE — кабинет сотрудника банка (staff-only)

**Статус:** демонстрационный standalone frontend · **Дата комплектования:** 22.10.2026 · **Данные:** синтетические.

**Опубликованный прототип:** https://vagner2203-cell.github.io/alfa-pulse-staff/

## Назначение

Это **только вклад кабинета сотрудника** для кейса «Умный кредитный кабинет предпринимателя». Клиентский кабинет, серверная система и полная интеграция сквозного кредитного процесса относятся к общему проекту команды и **не включены** в этот репозиторий. Публичный сайт на GitHub Pages остаётся по прежнему адресу.

## Реализовано в загружаемой версии

- Desktop-first интерфейс с верхней навигацией, оформлением ALFA PULSE и пульс-логотипом.
- Очередь из 8 синтетических заявок; поиск по ID/названию/ИНН и фильтры.
- Просмотр карточки заявки, синтетического балла 0–100, причин и истории.
- Демонстрационные действия: одобрить, отказать, запросить документ, предложить другие условия.
- Изменение статуса в таблице **только до обновления страницы**; экспорт CSV и сброс демоданных.

**Ограничение:** сайт не авторизует сотрудников, не проверяет настоящие документы, не сохраняет изменения между загрузками и не синхронизируется с клиентским кабинетом. Значения баллов уже заданы в данных и не вычисляются независимым скоринговым движком.

## Быстрый запуск

### A. Открыть локально

Откройте `index.html` в Safari / Chrome / Firefox. Интернет и установки не нужны.

### B. Запустить в Docker

Требуются Docker Engine + Docker Compose. В корне репозитория:

```bash
docker compose up --build -d
```

Откройте http://localhost:8080/ . Остановка: `docker compose down`.

**Граница Docker:** контейнер запускает только статический кабинет сотрудника, не банковский backend или PostgreSQL. Docker-сборку необходимо выполнить и подтвердить на машине команды (в среде подготовки пакета Docker Engine недоступен).

### C. Развернуть через GitHub Pages

Файл `index.html` уже расположен **в корне** архива. В существующем репозитории GitHub `alfa-pulse-staff`: загрузите `index.html` и остальные материалы, не создавая дополнительной корневой папки; выберите Settings → Pages → Deploy from a branch → `main` → `/ (root)`. Публикация текущей версии может изменить действующую страницу — перед заменой сохраните копию и проверьте изменения.

## Сценарий показа — 3–5 минут

1. Открыть главную страницу сотрудника, показать показатели и очередь.
2. Поиск `AP-1048` → открыть заявку ООО «Северный склад» → показать запрошенный продукт, сумму, балл и причины.
3. Нажать **«Предложить условия»** → задать сумму и срок → сохранить → показать статус «Другие условия».
4. Снять фильтры, открыть `AP-1045` → показать запрос выписки и действие **«Запросить документы»** (файл в демо не загружается).
5. Показать одобрение/отказ на отдельной тестовой заявке, историю и CSV-экспорт.
6. Честно пояснить, что результаты после обновления страницы обнуляются и что полная интеграция ещё не выполнена.

## Документация и проверки

- `docs/ARCHITECTURE.md` и `docs/diagrams/architecture.png` — фактическая и целевая архитектура.
- `docs/STATE_MACHINE.md` и `docs/diagrams/states.png` — целевые состояния (не enforcement в текущем UI).

Прогнать локальные проверки можно командой `npm test` при установленном Node.js >=20. Внешних npm-зависимостей нет.

## Требования общего кейса, которые закрываются командой, но не этим вкладом

Согласно исходному кейсу нужна единая работающая связка двух ролей, серверные переходы, хранение, проверка документов, моделируемое завершение кредитной сделки, Docker всего решения, API и тестируемый E2E. Staff-only пакет **не является автономной полной сдачей исходного кейса**. После интеграции команда должна указать commit SHA/tag финальной версии. См. `docs/SUBMISSION_SCOPE.md`.

## Финальная фиксация версии

В GitHub откройте список коммитов, скопируйте полный SHA текущего коммита и передайте команде. Здесь SHA не указан, потому что он формируется только после фактической загрузки архива в ваш репозиторий.
